## Findings

### P1 — review loops

**F1. The reviewer's verdict parser rejects any prose around the JSON.**
[review.ts:69](../server/src/agents/review.ts#L69) runs `JSON.parse` on the whole reply. It strips
only a code fence that wraps the entire reply. Reviewers routinely add a sentence:

- haiku: a fenced `{"decision":"approved","feedback":""}` block followed by "The document accurately describes the bug…"
- sonnet: "Everything checks out exactly against the repository.\n\n{\"decision\":\"approved\",…}"

In each case the action fails with *"Reviewer must return a valid approval decision and actionable
feedback"*, and an **approved** verdict is thrown away. Observed in 5 of 5 plan-loop runs and 1 of 2
implement-loop runs. Suggested fix: take the last fenced or balanced `{…}` that parses and has a
`decision`. If none parses, send the reviewer one "reply with only the JSON" turn before failing.

**F2. The plan-loop reviewer never sees the user's `ask_user` answers.** The review context is the
action's instructions plus any follow-up ([review.ts:20](../server/src/agents/review.ts#L20)). In
"Add a tax helper" I answered two rounds (percent rate, reject > 100, round to cents). All 4 review
prompts lacked those answers. The reviewer kept demanding that the *Decisions* "be moved to Open
questions … without first asking the user", and the loop stopped after 3 corrections. The seeded
Solidify Reqs prompt asks for "Decisions (each with the answer I gave)", so it conflicts with its own
reviewer whenever the user answers. Suggested fix: pass the run's Q&A (question → answer) into the
review context, and tell the reviewer that the Decisions come from the user.

**F3. An implement loop hands the *reviewer's* session to the next visit.** On approval the run's
`sessionId` is the reviewer's (`outcome(review)` at
[review.ts:76](../server/src/agents/review.ts#L76)). After Review → *Send back to Fix*, *Continue
the previous session* resumed that session as the author
([coding-agent.ts:355](../server/src/actions/coding-agent.ts#L355)). Here is what happened:
- Fix #1: author session `7e104ab2`, reviewer session `dd1e0760`, and the run saved `dd1e0760`.
- Fix #2 opened with "Resuming Claude Code session dd1e0760".
- That "author" did the work, then replied with a JSON verdict, as it had been trained to earlier in that session.
- The new reviewer was handed JSON as the "Implementer's summary" and answered in prose, so F1 failed the action.

The same `run.sessionId` is used for *Request changes* follow-ups
([coding-agent.ts:345](../server/src/actions/coding-agent.ts#L345)). This is the carry-over rule
that architecture candidate #7 targets. Suggested fix: keep the author's session as the run's
continuation session, and store the reviewer's separately.

### P2

**F4. MR Host "auto" treats every non-github.com remote as GitLab, so the push itself fails.** With a
plain remote (here a local bare repo; equally Bitbucket, Gitea or Azure DevOps), `git push -o
merge_request.create …` fails with "the receiving end does not support push options", and **the
branch is not pushed**. The code comment says this is by design
([open-merge-request.ts:80](../server/src/actions/open-merge-request.ts#L80)), but the option is
labelled "Detect from the remote URL". Suggested fix: use GitLab push options only for GitLab hosts,
or retry a plain push when options are refused. Then fail on *Require a merge request link* with a
clear message.

### P3

- **F5. Retry of a failed loop starts over from the draft.** It opens a new author session and redoes
  the author turn, even when only the review step failed. For Solidify Reqs that would re-ask every
  question. Quota waits keep their phase; retries don't.
- **F6. A missing output renders as an empty string mid-sentence.** After the MR action was skipped,
  the seeded *Merged* gate read "Approve once  is merged; that archives the task."
- **F7. A failed shell action shows its stderr twice:** once streamed, then again inside the error line
  ("soft failure / Command exited with code 3 / soft failure").
- **F8. Command output inside an agent's summary loses its line breaks.** The CI loop's `npm test`
  output rendered as one paragraph in the chat.
- **F9. Truncated selects.** The Retry dialog shows Agent as "Claude Cod", and Details → Effort shows
  "No overrid".
- **F10. Accessible names don't contain the visible label** (WCAG 2.5.3). The **Skip** button is named
  "Carry on with the next action", and **Try now** is named "Try again before the reset time".
  Voice-control users can't say the word they see.
- **F11. At 375px, a long branch chip** (`add-a-cart-item-count-afaad389`) overflows its card.
- **F12. `POST /api/connections` accepts a Jira connection with every required field missing**
  (201). *Test* then explains clearly, and the UI may already guard against this.
- **F13. The `verify-agentify` skill's feature map is mostly missing.** Its README indexes about 24
  files, but only 4 exist (`.claude/skills/` is untracked, possibly still being written).

## What worked

- **New task dialog:** manual repository entry, branch list read from the repo, worktree checkbox. **Move dialog** lists the stage's actions.
- **Shell actions:** regex outputs, `$WM_OUTPUT_FILE` outputs, `WM_ATTEMPT` (1 → 2 on re-entry), and `.env` carried into the worktree.
  - `continueOnFailure` carried on; a hard failure stopped the list.
  - Disabled actions are listed as "Switched off".
  - Retry after fixing the cause worked.
- **Write artifact** interpolated earlier outputs.
- **Standalone approval:** instructions interpolated, artifacts and diff shown.
  - *Send back* asked for a note, which set `lastFeedback`. Approving cleared it.
  - The note reached the resumed Fix prompt through `{{task.lastFeedback}}`.
- **CI loop:** check → fix → recheck went green after 1 correction (after switching OpenCode → Claude on Retry).
  - *Request revision* resumed the same session ("Revision 1"), added a test, and went green again.
  - Usage accumulated across rounds (`priorMs` kept).
- **Quota wait:** detected from Codex's message with the right reset time ("carries on at 2:31 AM").
  - Shown on the card, in the drawer and in the Stopped counter.
  - Setting the task's agent override to Claude, then *Try now*, ran in a **fresh** Claude session, not Codex's, and saved `summary.md`.
- **Restart mid-run:** the run became `interrupted` ("Server stopped while this action was running"), with no orphaned child process.
  - Retry then **Cancel** (confirm dialog) killed the child process.
  - Skip carried on to Done.
- **Archive:**
  - The action refused a dirty worktree.
  - The dialog offered *Discard changes and archive* up front.
  - The worktree was removed, the branch and artifacts were kept, and the read-only archived drawer opened.
  - The seeded *Merged* approval auto-archived the Bugfix task.
- **Concurrency limit 1:** the second agent run queued, and started as soon as the first finished.
- **`ask_user` questions:**
  - Two rounds, with the option + note answer format ("… — and reject rates above 100").
  - *Use recommended* pre-selects without sending; *Let it decide* worked.
  - Open conversations queues and empties correctly; the tab title shows "(1) Agentify".
- **Workflow editor:**
  - Loop mode change saved, applying from the next visit.
  - The unsaved-changes guard (cancel keeps the edit, accept discards it).
  - The server refuses deleting a stage with active tasks (409), duplicate action keys, and template expressions in shell commands.
- **Workspaces:** *Clone* copied workflows (including edits) and agent defaults, but not tasks.
- **Connections:** secrets are write-only, HTTPS is required, and an unreachable host fails clearly.
- **Agents page:** Test agent (Claude replied "pong" in 6.2s; Codex showed its quota message), and per-agent defaults.
- **Isolation:** the sandbox repo's checkout stayed on `main`, untouched, throughout. The server log stayed clean.
