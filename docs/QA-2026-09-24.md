# Workflow Manager — live end-to-end QA, 24 September 2026

## Verdict

**The engine held up under real agent runs; the planning ("grilling") loop works. Two P1 issues
affect what reaches the agent and what you can review.** Agents asked good questions and revised
in the same session. Usage limits, Send back, verification and archiving all behaved. However,
feedback notes leak into later stages' prompts, and new files are invisible in every review diff.

## Findings

### P1

**F1 — Feedback leaks into later stages' prompts.** `requestChanges` saves the note as
`task.lastFeedback` ([engine.ts:568](../server/src/engine/engine.ts#L568)). Nothing clears it on
approve or stage change. As a result:
- My Plan-stage note ("drop the e2e scenario…") reached the **Build** agent as "Reviewer feedback".
- On the seeded Feature workflow, the implementer was told *"Reviewer feedback from a previous
  attempt: … Fold these into the requirements and remove the Open questions section."* That
  instruction was meant for the requirements agent.

Suggested fix: clear `lastFeedback` when a gate is approved, or scope feedback to the stage or run it
was given in. Make `{{task.lastFeedback}}` mean "why this stage was sent back to".

**F2 — New files can't be reviewed.** [diff.ts](../server/src/services/diff.ts) lists untracked
files with 0 lines, and `readPatch` leaves them out. The card said "6 files, +120 −6" and hid the
two new files (267 lines): the helper and its tests, the core of the change. They are marked
"untracked" with no expand arrow. Every workflow whose agent doesn't commit is affected (the Plan &
Build prompt said "commit nothing"). Suggested fix: diff untracked files with
`git diff --no-index /dev/null <file>` or with an intent-to-add in a temporary index.

### P2

**F3 — Grilling questions can't take a free-text answer.** `ask_user` choice questions are pure
radios ([mcp.ts](../server/src/api/mcp.ts)). The agent offered "Something else (tell me your
preferred keys)", but there is no box to type into, and you can't pick an option *and* add nuance.
The tool description ("ask everything … at once … only when you are actually stuck") also works
against a grilling prompt; the agent complied only because the prompt overrode it. Suggested fix:
add an "Other…" text field to every choice question and an optional note per answer, and soften
the description.

**F4 — Usage and duration are overwritten each round.** Request changes and quota resume reuse the
run row and replace `usage` and `startedAt`. The plan run showed 354.6k in / $0.25, then
34.3k / $0.03 after one revision. Totals under-report any run with revisions. Suggested fix:
accumulate across rounds.

**F5 — The seeded Solidify Reqs never asks questions.** Its prompt doesn't mention `ask_user`, so
the four real decisions ended up under *Open questions* in `requirements.md`. You answer them in
the free-text revision box, and if you approve without answering, Implement guesses. The Plan &
Build grilling prompt works well (below); consider seeding something like it.

**F6 — The seeded Test Imp runs nothing, and says so nowhere.** *Install dependencies* and *Run
tests* ship switched off. The drawer hides disabled actions, so Test Imp shows only "1. Manual QA"
with empty instructions. The reviewer isn't told no tests ran. Suggested fix: show disabled actions
greyed out, or seed Manual QA instructions that say tests are off until configured.

**F7 — The chat doesn't follow a revision.** After *Request revision*, the transcript stayed on the
**old** plan (scrollTop 2917 of 4408) beside "Ready for review · Revision 1". It is easy to approve
the wrong text. Suggested fix: scroll to the new result when the run settles.

**F8 — A clean workflow editor goes stale after an external save.** After a save from elsewhere,
the sidebar updated but the unedited editor kept the old 2-stage version and switched to *Unsaved
changes*. Save then correctly refused ("changed in another window. Reload before saving"), but the
banner has no Reload button; Discard is the way out. Suggested fix: a clean editor should adopt the
new version, and the conflict banner needs a Reload action.

**F9 — Archive leaves the worktree folder behind with a live junction.** With
`carryOver: client/node_modules`, `git worktree remove` unregistered the worktree but left
`worktrees/<task>/client/node_modules` → a junction to the repo's real `node_modules`. The repo's
copy survived. However, Windows PowerShell 5.1 `Remove-Item -Recurse` can follow junctions, so a
user who later clears leftover folders could empty the repo's `node_modules`. Suggested fix:
unlink the carried-over junctions before `worktree remove`, then remove the empty directory.

**F10 — Questions still time out after about 339 seconds** (Claude Code 2.1.267, as noted in
DESIGN §3.1). The probe's question timed out twice. Each time the agent asked again, and the app
replaced the question cleanly ("stopped waiting … asked again"). **A typed but unsent answer
survived the swap.** This is survivable, but it depends on the agent choosing to ask again, and a
draft keyed by question id could attach to a different question if the wording changes.

### P3

- **F11** The approval composer ("What would you like changed?", textarea enabled) is visible while
  the agent is still running or asking. It competes with the question form and invites typing an
  answer into the wrong box.
- **F12** *Save result as* keeps the chat preamble: `plan.md` started with "I have everything
  needed. Here's the plan." and `requirements.md` with "Now I have enough context…".
- **F13** Every first run logs `template.unresolved … {{task.lastFeedback}} is missing`, although an
  empty feedback block is the normal case for the seeded prompts.
- **F14** On first load of Agents, Ticket drafting flags its own default `gpt-5.6-luna` as "not
  recognised — pick one from the list" until the Codex catalogue arrives. The flag clears on reload.
- **F15** Model chips are inconsistent. While running, the drawer chip shows only "Claude Code";
  model and effort appear after the run. The editor's stage chip omits effort ("Claude Code ·
  sonnet" with medium set). In the action form, Model says "Default" where Agent says "Stage
  default (Claude Code)".
- **F16** Stage settings with Agent *None* lists every agent's models in one flat list (60+).
- **F17** Gate actions differ by place: the drawer has *Review & revise* + *Send back to Plan*,
  while the chat's approval card has *Request revision* + *Approve & continue* but no Send back.
- **F18** The Archive dialog doesn't warn about uncommitted work up front. You find out on click,
  though it then offers *Force archive* with a clear warning, which is good.
- **F19** Layout: on the 7-stage Feature board, the only active card was cut off at the right edge.
  The Archive table squashes to 4-line rows with a scrollbar when the drawer is open. Branch slugs
  cut words off (`…showdown-resul-9267b3e0`).
- **F20** A deliberate Cancel counts in the red *Stopped* header count, like a failure.

## What worked well

- **Grilling:** two rounds of three questions, each grounded in the code (e.g. "chat has a text
  input, how should shortcuts be gated?", matching an existing `INTERACTIVE_TAGS` convention), each
  with a recommended option. The plan recorded every answer. A revision took about 20 seconds in the
  same session.
- **Usage limit:** a real limit hit went to quota-wait, resumed the same session at reset, and
  showed the reset time on the card and timeline.
- **Send back** from Manual check re-entered Build, resumed the builder's session, and passed the note.
- **Isolation:** worktrees under the data directory; the repository's checkout was never touched;
  `.env` copied and `node_modules` linked.
- The shell stage's real test run (136 tests) streamed into the drawer.
- Archive failures are safe, explained and retryable. The archived task keeps its branch name and artifacts.
