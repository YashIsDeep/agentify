## Findings

### QA-05 — P2: Workflow catalogue stays stale in other tabs

**Steps**

1. Open the same empty workspace's Workflows page in tabs A and B.
2. In B, create a workflow called `QA second-tab workflow`.
3. Return to A. Navigate to Agents and back to Workflows.

**Actual:** B shows the saved workflow. A still shows `No workflows yet`, has no board entry, and displays `Live`. Reloading A immediately makes the workflow appear. The same behavior occurred when creating a workflow through the local HTTP API.

**Expected:** Other tabs should receive updated workflow lists without a manual reload, including new boards and changed stage definitions.

**Impact:** A user working in multiple tabs sees an outdated catalogue despite the live status. New workflows cannot be selected until reload. Code inspection also indicates existing stage/action definitions can stay stale; the browser reproduction specifically confirms creation visibility.

**Cause:** [App.tsx](../web/src/App.tsx#L22) caches workflows with `staleTime: Infinity`. [live.ts](../web/src/live.ts#L28) invalidates task, artifact, and run queries, but has no workflow-change subscription. [workflows.ts](../server/src/services/workflows.ts#L61) does not publish a workflow-change event.

**Suggested fix:** Publish workflow create/update/delete events and invalidate the workspace's workflow queries. Preserve dirty editor drafts and retain the existing optimistic concurrency conflict check.

Evidence: [stale tab A](qa-2026-09-16/stale-first-tab.png), [updated tab B](qa-2026-09-16/updated-second-tab.png).

### QA-06 — P3: Mobile navigation button overlaps Archive and task header text

**Steps**

1. Set the viewport to 390×844 and open Archive with navigation closed.
2. Open an archived task and view its artifacts.
3. Also inspect Archive at 768×1024.

**Actual:** The floating menu button covers the beginning of `Archive` and the task's `Archived` badge. Archive overlap occurs at tablet width too. At 768px, the button spans x=12–46/y=14–48 while the heading starts at x=28/y=28, confirming an intersection.

**Expected:** Reserve space for the navigation button in every affected header.

**Cause:** [styles.css](../web/src/styles.css#L3635) positions the toggle above content. The mobile inset only covers `.board-heading` and `.page-view > .page-header`; `.archive-header` and `.drawer-header` are omitted.

**Suggested fix:** Apply a shared mobile header inset, or reposition the toggle when the task drawer is open. Verify both themes and both narrow breakpoints.

Evidence: [phone Archive](qa-2026-09-16/mobile-archive-overlap.png), [phone task](qa-2026-09-16/mobile-task-overlap.png), [tablet Archive](qa-2026-09-16/tablet-archive-overlap.png).
