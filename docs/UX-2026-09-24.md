# Workflow Manager — end-to-end usability review, 24 September 2026

## Verdict

**The main path works on a fresh install, and the agent loop is pleasant to use.** Claude Code asked
good questions, revised in about 20 seconds, and built a working change in under a minute. The
friction is around the loop: one real rendering bug in the chat, the same diff approved three times,
and problems that could be caught before a run but only surface after several approvals.

## Setup

- Production build of `e8e28de`, served on `http://localhost:2814` with a **fresh** data dir
  `C:\code\wm-ux-data`, so the first-run state was what a new user sees. The launch config is
  `workflow-manager-ux-review` in `.claude/launch.json`.
- Target: `C:\code\wm-ux-repo`, a clone of the taskbook demo repo with no remote.
- Claude Code 2.1.267, CLI default model. Viewports: 1200×750, 390×844. Dark and light themes.

## Findings

### P1

**U1 — Switching chats leaves the previous transcript on screen.** After *Approve & continue* on
Draft requirements, I clicked the new **Implement** chat in the sidebar. The modal then showed both
transcripts stacked, each with its own *Raw log* bar. The live Implement transcript was squeezed to
about 100 px. Cause: [ChatModal.tsx:137-138](../web/src/components/ChatModal.tsx#L137) gives
`<Transcript>` and `<AgentReview>` the same `key={run.id}` as siblings. When the run changes, React
builds its old-children map by key, the second entry overwrites the first, and the old Transcript is
never deleted. Fix: give them different keys (e.g. `review-${run.id}`), or wrap both in one keyed
element.

### P2

**U2 — The same diff is approved three times on the Feature workflow.** *Implement* waits for
approval with the diff, then *Review Imp → Review diff* shows the same diff, then *Test Imp → Manual
QA* shows it again. Nothing changes between the first two gates. Suggest dropping Review Imp's
approval from the seed, or turning off Implement's own approval. Either way, one "review the code"
gate and one "try it" gate.

**U3 — Problems that could be checked up front appear only after the approvals.** Submit MR failed
on `git remote get-url origin failed (exit 2): error: No such remote 'origin'`. That was after three
approvals, and the repository never had a remote. The error is raw git output. *Retry* is offered
though it can't succeed. Suggest checking a workflow's requirements when a task enters it: a repo
for worktree and agent stages, and a remote plus `gh`/`glab` for Submit MR. Show the result as a
warning on the card or in the New task dialog. Explain the failure in plain words, with the next
step ("add a remote, or Skip").

**U4 — "Repository: Optional" on a workflow that needs one.** The Feature task with no repository
went straight into Solidify Reqs. *Ensure worktree* reported **succeeded: no repository**, with a
green tick. The read-only agent then ran in the artifacts folder with no code to read. Implement
would refuse later ([coding-agent.ts:174](../server/src/actions/coding-agent.ts#L174)). For a
workflow with worktree or agent actions, the dialog should mark Repository as needed, and
ensure-worktree should say "skipped", not "succeeded". The repo dropdown also defaults to *No
repository* even when one has been used before; defaulting to the last-used repo would save a step
on every task.

**U5 — An agent without a git identity rewrites the repo's shared config.** This machine has no
global `user.name`/`user.email`. To commit, the autonomous Implement agent ran `git config
user.email …` and `user.name "Yashparth Gupta"`, a name it guessed. It wrote them into the
worktree, which shares `.git/config` with the main checkout. So the user's repo config changed
silently, and the only record is one line in the chat. Suggest the Agents page (or ensure-worktree)
check `git config user.email` and warn. Or pass `GIT_AUTHOR_*`/`GIT_COMMITTER_*` settings from the
app so agents never touch config.

**U6 — A template value renders empty.** After Submit MR was skipped, the Merged gate read
"Approve once  is merged; that archives the task." The instruction is `{{outputs.openMr.mrUrl}}`
([seed/workflows.ts:202](../server/src/seed/workflows.ts#L202)). Suggest wording that reads well
with no value ("Approve once the merge request is merged…" plus the link when there is one), or
rendering missing outputs as a visible placeholder.

**U7 — Long action names vanish on a phone.** At 390 px, a failed agent row with *Retry* and *Skip*
squeezes `.run-label` ("2. Draft requirements") to **1 px wide**. Only the icons, the agent chip,
the time and the buttons are left. This is the same flex-shrink pattern as the chat rows fixed
earlier today. Give the label `min-width` and let the buttons wrap below it.

### P3

- **U8 Header says Running while the agent waits on you.** With a question pending, the chat header
  read "Running · 42s" and its timer kept counting. The sidebar ("Needs you"), the tab title ("(1)")
  and the chat list's "?" icon were all correct.
- **U9 Run time includes your review time.** Implement read "Ready for review · 53s". After I
  approved, it read "Succeeded · 2m 9s".
- **U10 A user cancel is labelled Failed.** After Cancel, the card and the drawer badge say
  **Failed**, while the timeline says "Cancelled by user". This goes beyond F20, where only the
  count was at issue.
- **U11 Cancel is one click on a small square icon**, with no confirmation, next to the step's
  timer.
- **U12 The review card for a read-only step shows an empty diff.** Draft requirements' review
  card and drawer card both carry "Changes on wm/… 0 files, +0 −0 · Nothing has changed against
  main yet". It is noise for a step that isn't allowed to change files. The card's instruction
  "Read requirements.md under Artifacts" points at a tab hidden behind the modal. Show the artifact,
  or link to it, instead.
- **U13 The chat is cramped while reviewing.** At 750 px tall, the review card (diff list, feedback
  box, buttons) leaves the transcript about 320 px. An expanded file diff scrolls inside the card,
  which scrolls inside the modal. The patch shows raw `index …`/`---`/`+++` headers. A resizable
  split, or opening a diff full width, would help at the gate that matters most.
- **U14 Button emphasis when the box is empty.** On the review card, *Request revision* is the
  primary (teal) button even while it is disabled and empty. *Approve & continue*, the common action,
  is secondary. Swap the emphasis based on whether feedback has been typed.
- **U15 Revisions can't be compared.** After *Request revision*, the new draft replaces the old one
  in place. Nothing shows what changed between drafts.
- **U16 Chat noise on each round.** A revision appears three times: as your bubble, as a *Prompt*
  row, and in "Carrying on in Claude Code session 86640310-…". Each round also repeats "Claude Code
  can ask you questions while it works" and the session id. Tool rows print absolute worktree paths
  (`C:\code\wm-ux-data\worktrees\add-a-remove-command-cdb8d976\src\cli.js`) where `src/cli.js`
  would do.
- **U17 Internal action type ids are shown.** Step rows read "Ensure worktree `ensure-worktree`",
  "Move to next stage `move-stage`", "Review diff `approval`". The editor has "Ensure worktree /
  Ensure worktree" and "Move to next stage / Move to stage" as title and subtitle.
- **U18 Questions: "Recommended" is prose, not a state.** Each recommended option ends in
  "(recommended — …)", but nothing is preselected and there is no "accept recommendations" action.
  "Something else (please specify)" options duplicate the free-text box under every question. The
  question card's amber fill is the heaviest colour block in the app.
- **U19 Moving a task is only possible from the stepper dots.** The drawer has no "Move to next
  stage" button. The stepper dots are the control, and a Move dialog opens even for a stage with no
  actions, with a "Run its actions" checkbox that does nothing there ("To Pick has no actions").
- **U20 After approving, the chat stays on the finished run.** The next stage's agent appears in the
  chat list, but the chat itself stays on the old run. A "Follow Implement →" link would save a click.
- **U21 Archive doesn't show where the work went.** The Archive table has Task / Workflow / Last
  stage / Archived, but no branch. The task was archived with its MR step skipped, so the branch was
  never pushed. Nothing says so at archive time.
- **U22 Truncated controls.** "The repo's current…" (New task, base branch), "Needs a mode…"
  (Agents, effort placeholder for OpenCode/Cursor), "Search titles, tags, workfl…" (Archive).
  *Test agent* is enabled for Cursor while it shows *Not logged in*.
- **U23 First run has no guidance.** A new install opens on an empty 7-column Feature board. Nothing
  suggests checking Agents or says the workflows expect a repository. The "No tasks yet" pill floats
  over the column borders.

## What worked well

- **Questions:** the agent's first round found a real latent bug (ids collide after a removal,
  because `add()` uses `items.length + 1`) and offered to fix it. The free-text box carried my
  "use max existing id + 1", and the requirements recorded every decision.
- **Revision loop:** the note came back as a new draft in the same session in about 20 s. The view
  jumped to the new draft, and the version chip moved from "First draft" to "Revision 1".
- **Status cues:** "Needs you" in the sidebar, the "(1)" tab title and the "?" in the chat list all
  appeared when attention was needed and cleared when it wasn't.
- **Isolation:** the worktree kept the checkout on `main` throughout. The failed MR step was safely
  skippable. Archive was clean.
- The task drawer, Workflows editor, Agents and Connections pages are consistent with the design
  system, and light theme holds up.
